# アカウント全体を検索する

エマはコミック、レコード、トレーディングカードを集めています。コレクションは 3 つ、アイテムは数百点、コピーはその倍あります。ある人から「表紙が黒いスパイダーマンの号はまだ持っている?」と聞かれました。それがどのコレクションに入っているかまで覚えている必要はないはずです。

検索は、ひとつの入力欄からその質問に答えます。言葉を入力すると、KolleK はアカウントにあるものを一度に見に行きます。アイテム、コレクション、コピー、写真、貸出、保管場所、セット、シリーズ、カテゴリ、タグ、書類です。

サイドバー上部の **検索** から開くか、どの画面からでも **⌘K**（Windows と Linux では **Ctrl K**）を押してください。

## 何が検索されるか

検索は名前だけを見るわけではありません。レコードの周りに紐づけられた言葉も見ます。単なる文字どおりの一致ではなく実用的になるのは、そのためです。

`spider` で検索すると、次のものが見つかります。

- **Amazing Spider-Man #300** というアイテム
- コピー **ASM-300-B**（属するアイテムがその名前だから）
- `spider-man-300-front.jpg` という写真
- 「Spider-Man」と名付けたことのないアイテム（**spider-man** タグを付けてあるから）
- 友人への貸出（貸し出しているコピーがそのコミックだから）

タグ、カテゴリ、保管場所から始まった検索でも、本当に探していたものにたどり着けます。

:::note
ごみ箱にあるものは検索対象から外れます。@doc(dataSafety.restoreFromTrash, "復元する")と、また見つけられるようになります。
:::

## 一致の仕組み

規則は 4 つだけです。

**入力した語はすべて一致する必要があります。** 語を足すと結果は広がるのではなく絞り込まれます。`miles davis` は両方の語がどこかに現れるレコードだけを見つけます。結果が多すぎるときは語を足してください。

**語は先頭から一致します。** `spi` と入力すれば **Spider-Man** が見つかります。語を最後まで打つ必要はありませんが、先頭から打つ必要はあります。`man` で検索しても **Spider-Man** は見つかりません。`man` はどの語の先頭でもないからです。

**大文字小文字と記号は無視されます。** `asm-300`、`asm 300`、`ASM_300` はすべて同じように扱われます。自分の付けた識別子がハイフンなのかドットなのかアンダースコアなのか思い出せないとき、これが効いてきます。

**1 文字だけの語は無視されます。** 単独の 1 文字はありふれすぎていて索引化する意味がないため、検索語から外されます。1 文字だけで検索した場合は、すべてではなく何も返りません。

## 結果の読み方

結果は種類ごとにまとめられ、アイテムが先頭に来ます。各行には名前、どの種類のレコードかを示すバッジ、（あれば）属するコレクション、そして 1 行の補足が並びます。アイテムのコピー数、コピーの保管場所、貸出先などです。

各行の右側の **名称に一致** は、入力した語がすべてレコード自身の名前に現れたことを意味します。**本文に一致** は、少なくとも 1 語が説明文やタグなど、もっと外側で見つかったことを意味します。名称に一致したものが上位に並ぶため、いちばん近い答えはたいてい先頭の行です。

結果の上のチップで、1 種類のレコードだけに絞れます。それぞれが独自の URL を持つので、アイテムだけの検索をブックマークしたり、同じアカウントの同僚に共有したりできます。

表示されるのは最大 50 件です。それを超えるときは、一覧の下に全部で何件一致したかが出ます。目当てのものにたどり着く一番早い方法は、検索語をひとつ足すことです。

## 誰が何を検索できるか

検索は自分のアカウントの中だけで行われます。他のアカウントのものが見えることはありませんし、外部の人があなたのものを見ることもありません。

アカウントの中では、どの権限でも検索でき、結果はその権限で開ける画面だけを開きます。ひとつだけ例外があり、@doc(accounts.usersAndRoles, "閲覧者")にはタグ単独の結果が出ません。タグを管理する画面は所有者と編集者だけのものだからです。それでも `spider-man` タグの*付いた*ものはすべて見つかります。タグ名は、それを持つアイテムの側にも数えられているからです。

## 見つからないものがあるとき

検索は、作業に合わせて更新される索引を読みます。新しいアイテムは保存した時点で見つけられます。

一時的に遅れる場合が 2 つあります。

**他のレコードが名前を参照しているものを改名したとき。** コレクションを改名すると、その中のアイテムをすべて新しい名前で索引化し直す必要があります。これは背後で行われるので、少し待ってください。

**セルフホストのインスタンスを更新した直後。** 既存のインストールでは索引は空から始まり、一度組み立てる必要があります。@doc(selfHosting.cliCommands, "再構築コマンド")を実行すれば、すべて見つけられるようになります。

```bash
php artisan search:rebuild-index
```

このコマンドはいつ実行し直しても安全なので、索引がずれてしまったときの対処法でもあります。

## 次に読むもの

- @doc(items.tagAndFind) はタグ付けを扱います。文字どおりに名付けていないものを検索が見つけられるのは、これのおかげです。
- @doc(organizing.categoriesSetsAndSeries) は、同じく検索に流れ込むカテゴリ、セット、シリーズを説明します。
- @doc(photos.library) には専用の検索があります。アカウント全体ではなく写真を見ていくときに向いています。
